# 배포

모두의 AI 실험실 테스트베드 서버 기준. 구조는 **nginx(프론트) → FastAPI(백엔드) → PostgreSQL**
컨테이너 3개이고, 전부 `docker compose` 하나로 뜬다.

```
    브라우저 ──▶ :80  nginx        /        → 정적 파일(Vite 빌드 결과)
                                  /api/    → backend:8000
                     backend      ──▶ postgres:5432
                                  ──▶ DART · 국세청 · KIPRIS · Tavily · LLM
```

프론트는 API 주소를 모른다. `VITE_API_BASE_URL=/api/v1` 상대경로라 **서버 IP 가 바뀌어도
다시 빌드할 필요가 없다.** 같은 출처라 CORS 도 타지 않는다.

---

## 서버에 필요한 것

- Docker 와 Docker Compose v2 (`docker compose version` 으로 확인)
- 80 포트 개방 (보안그룹·방화벽 양쪽)
- 디스크 여유 5GB 이상 — DART 의 corpcode.xml 만 30MB 이고 수집한 원문이 쌓인다

---

## 최초 배포

```bash
git clone <repo> && cd 2026-Finance-AI-Challenge/biz-lantern

# 1) 백엔드 환경변수. .env 는 git 에 없으므로 직접 만든다
cp apps/backend/.env.example apps/backend/.env
vi apps/backend/.env          # 키를 채운다 (아래 표 참고)
chmod 600 apps/backend/.env   # 서버에 API 키가 평문으로 놓인다

# 2) 기동
docker compose up -d --build

# 3) 확인
docker compose ps
curl http://localhost/api/v1
```

`DATABASE_URL` 은 `.env` 에 뭐라고 적든 **compose 가 덮어쓴다**(`docker-compose.yaml` 의
`environment`). 컨테이너 안에서 DB 호스트는 `localhost` 가 아니라 `postgres` 인데, 이걸
매번 틀리기 때문에 아예 못 박아 뒀다.

| 키 | 필수 | 없으면 |
|---|:--:|---|
| `DART_API_KEY` | ✅ | 앱이 아예 뜨지 않는다 |
| `NTS_API_KEY` | ✅ | 앱이 아예 뜨지 않는다 |
| `KIPRIS_API_KEY` | | 특허 정보만 비어서 나온다 |
| `TAVILY_API_KEY` | | 뉴스 검색(챗봇)이 502 |
| `OPENAI_BASE_URL` / `_API_KEY` / `_MODEL` | | 챗봇 500. 보고서는 룰베이스 정형문으로 저하 동작 |

## 재배포 (코드 수정 후)

```bash
git pull
docker compose up -d --build
```

`data` 볼륨과 DB 는 그대로 남는다. 만들어둔 보고서도 유지된다.

## 확인 절차

실패한 지점이 곧 원인이다. 위에서부터 순서대로 본다.

```bash
docker compose ps                       # 3개가 다 Up 인가
curl http://localhost/api/v1            # {"status":"ok"} 인가
docker compose exec postgres psql -U postgres -d biz_lantern -c "\dt"
                                        # 테이블 5개가 있는가
curl "http://localhost/api/v1/companies/트래블월렛"
                                        # 이 서버 IP 에서 외부 API 가 열리는가
```

보고서(가장 무거운 경로, 수 분 걸린다):

```bash
curl -X POST http://localhost/api/v1/reports \
     -H "Content-Type: application/json" -d '{"corp_code":"01685996"}'
# 202 + report_id 를 받고, 아래를 status 가 바뀔 때까지 반복한다
curl http://localhost/api/v1/reports/<report_id>
```

마지막으로 브라우저에서 `http://<서버IP>/` → 검색 → 상세 → 보고서 → 챗봇을 한 번 통과시킨다.

## 접근 제한 (권장)

공개 URL 을 그대로 두면 누구나 보고서 생성을 눌러 **DART 일일 20,000건 한도와 LLM 요금**을
태울 수 있다. nginx basic auth 로 막는다.

```bash
docker compose exec frontend sh -c \
  "apk add --no-cache apache2-utils && htpasswd -bc /etc/nginx/.htpasswd <아이디> <비밀번호>"
```

그리고 `apps/frontend/nginx.conf` 의 `location /` 안에 두 줄을 넣고 재빌드한다.

```nginx
auth_basic "biz-lantern";
auth_basic_user_file /etc/nginx/.htpasswd;
```

(컨테이너에 넣은 `.htpasswd` 는 재빌드하면 사라지므로, 계속 쓸 거면 볼륨으로 마운트한다.)

## 막혔을 때

| 증상 | 원인 |
|---|---|
| backend 가 재시작을 반복 | `.env` 누락 또는 `DART_API_KEY`/`NTS_API_KEY` 없음. `docker compose logs backend` |
| 화면은 뜨는데 API 만 전부 실패 | nginx 가 backend 에 못 닿음. `docker compose ps` 로 backend 상태 확인 |
| 새로고침하면 404 | nginx SPA fallback 문제. `nginx.conf` 의 `try_files` 확인 |
| `/companies/{name}` 이 502 | 응답이 300초를 넘김. `nginx.conf` 의 `proxy_read_timeout` 을 늘린다 |
| 보고서가 계속 PENDING | 정상일 수 있다(DART 원문 3건 + 항목별 LLM 호출). `docker compose logs -f backend` |
| 재배포 후 보고서가 사라짐 | `backend_data` 볼륨이 안 붙었다. `docker volume ls` |

## 알아둘 것

- **uvicorn 워커는 1개다.** 보고서 생성이 `asyncio.create_task` 로 돌고 LLM 호출이 무거워서,
  워커를 늘리면 동시 생성이 겹쳐 메모리와 요금이 튄다.
- 백엔드의 `data/` 경로는 전부 CWD 기준 상대경로다. Dockerfile 의 `WORKDIR /app` 이 그
  기준점이라 바꾸면 저장 위치가 통째로 어긋난다.
- **외부에 열리는 포트는 80 하나뿐이다.** backend 는 호스트 포트를 아예 열지 않고(같은
  네트워크의 nginx 만 `backend:8000` 으로 닿는다), postgres 는 `127.0.0.1` 에 묶여 있다.
  DB 비밀번호가 `postgres/postgres` 라 이 바인딩을 풀면 안 된다 — 밖에서 DB 를 봐야 하면
  SSH 터널을 쓴다: `ssh -L 5432:127.0.0.1:5432 <user>@<서버IP>`
- backend 컨테이너를 직접 찔러볼 때는 `docker compose exec backend sh` 를 쓴다. 호스트
  8000 을 열지 않은 이유는 팀원이 로컬에서 돌리는 `uv run fastapi dev` 와 부딪히기 때문이다.
